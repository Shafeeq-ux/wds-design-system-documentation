Pattern purpose

Copy written with translation in mind costs less to localise and doesn't break layouts when the site is translated, for example into Canadian French. The examples below use en-US and fr-CA.

Voice and tone

The voice stays the same in every language: clear, confident, concrete. Translators should adapt idioms and examples, not translate them word for word.

Writing rules

  • Leave room to grow. French and German run about 30% longer than English, and short strings like buttons can grow by 100%. Aim for 70% of each character limit in English.
  • Avoid idioms, puns and cultural references: "move the needle", "home run", "slam dunk".
  • Write full sentences rather than strings assembled from pieces. Word order changes between languages.
  • Never put text in images. It can't be translated, searched or read by screen readers.
  • Keep product names in English: Automotive Retail Cloud, T1, Tekion One.
  • Use one term per concept (for example "rooftop", not "rooftop", "location" and "store" interchangeably) so translation memory stays consistent.

Character or word limits

Use the Character limits page, and check translated copy against the same limits. If a translation doesn't fit, rewrite it. Don't shrink the text style.

Approved examples

Translates well

  • "Close deals faster with one connected desk."
  • "Every Department. Every Role. One AI."

Translates badly

  • "Hit the ground running on day one."
  • "T1 is a game-changer."
  • A headline built from "Save" + {number} + "hours a week"

Accessibility and localisation notes

  • Set lang="en-US" or lang="fr-CA" on <html>, and hreflang on links between language versions.
  • Test every section with long translated copy at mobile width before launch.
  • Right-to-left languages aren't planned. If they are, the layout tokens will need logical properties (margin-inline).
