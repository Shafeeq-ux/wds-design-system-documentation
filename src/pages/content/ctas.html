Pattern purpose

CTA labels tell people what happens when they select a button or link. A good label makes the next step obvious and sets the right expectation.

Voice and tone

Direct and active. The label describes the action from the visitor's side ("Request a Demo"), not the system's ("Submit").

Writing rules

  • Start with a verb: Request, See, Watch, Read, Explore, Register, Get.
  • Title Case, as in Figma, and no end punctuation.
  • 2–4 words. Every word should earn its place.
  • Make it specific. "Watch Video" beats "Learn More" when the link opens a video.
  • Keep one label per action across the site. If the demo CTA is "Request a Demo" in the footer, it's "Request a Demo" everywhere (not "Request Demo" in one place and "Book a Demo" in another).
  • Pair actions by weight: one primary ("Request a Demo"), one secondary or tertiary alternative ("See AI in Action").

Inconsistency in Figma. The file uses "Request Demo", "Request a Demo", "Learn more" and "Read More" in different places. Proposed standards: Request a Demo for the main conversion, and Read More for article cards.

Accessibility and localisation notes

  • Link text must make sense on its own (WCAG 2.4.4). When several cards say "Read More", add hidden context: Read More<span class="visually-hidden"> about Deal Guard AI</span>.
  • Label in name (WCAG 2.5.3): if you add an aria-label, it must start with the visible label.
  • Say when a link opens something unexpected: a new tab, a PDF or a video pop-up.
  • Allow 30% more length for translation. Buttons never wrap, so shorter English labels give translators room.
