Overview

WDS colour comes in three layers. Designers and developers should almost always use the semantic layer: it carries the meaning of a colour and switches automatically between light and dark.

Primitive palette

The palette is mostly neutral. Gray runs from gray-0 (white) to gray-950 (near-black), and teal is the single brand accent. Status colours are reserved for feedback.

Static

Static colours never change with the theme. Use them for content that must stay the same, such as type on a photograph.

Backgrounds

Use bg-page for the page and default sections. Use bg-subtle or bg-recessed to separate alternate sections without a border, and bg-inverse for a high-emphasis band such as a closing CTA.

Text

Contrast is measured against bg-page in each theme. Body copy needs at least 4.5:1 (AA). Text at 24px and up, or 18.66px bold and up, needs 3:1.

Icons

Borders

Use border-subtle for dividers, border-default for cards and inputs, and border-strong for hover. border-focus is only for focus rings.

Status

Status colours always come as a set: background, border, text and icon. Never rely on colour alone. Pair it with an icon and a text label (WCAG 1.4.1).

Light and dark theme

Every semantic and component token has a light and a dark value. Most dark values aren't a simple inversion: surfaces step up from gray-950 (page) to gray-900 (subtle, elevated) to gray-850 (recessed), so depth comes from lightness, not shadows.

  • Default: pages render light.
  • System: pages follow the visitor's operating-system setting through prefers-color-scheme.
  • Forced: set data-theme="dark" or data-theme="light" on <html>, or on any section to theme only that section.

Status backgrounds in dark mode are translucent (for example #10b9811f), so they tint whatever surface they sit on.

Accessibility

These pairs are checked in both themes on every build. Ratios for translucent backgrounds are measured after compositing over bg-page.

Known issues

Raise these with Design before the related components ship.

  • Primary button in dark mode is unreadable. btn-primary-bg-default is #ffffff and btn-primary-text-default is also #ffffff (1:1). The dark text value should probably be gray-800.
  • Primary button colour doesn't match its token. Figma draws the primary button with a blue gradient, but the token is gray-800. One of them needs to change.
  • Teal text fails on light backgrounds. text-teal (teal-500) is 2.22:1 on white. Use it only on dark backgrounds or for large decorative type, or point the light value at teal-700 (5.68:1).
  • Error text is just under AA in light mode. status-error-text on status-error-bg is 4.39:1. Use status-error-text-strong for small text.
  • Input borders are too faint to identify a field. border-default is about 1.4:1 against the page. WCAG 1.4.11 needs 3:1 for the visual boundary of a control. Even border-strong is only 1.82:1, so field borders need gray-400 (3.22:1) in light and gray-500 (3.64:1) in dark.
  • Input and checkbox backgrounds are 15% gray. They're designed to sit on gradients and images, so on a plain page they look transparent.
