Overview

The header is the site's main navigation. It holds the Tekion logo, five top-level menus, Login, Request Demo and a menu button. It's always dark, whatever the page theme, so the teal logo and the white menu button stand out on every page.

Variants and states

Figma has one variant per breakpoint. Switch the preview viewport to see each one. The menus and the menu panel are proposed: Figma doesn't show them open.

Design guidance

  • Keep top-level menus to five or fewer, and labels to one to three words.
  • "Request Demo" is the header's call to action. Don't add a second one.
  • Use the same header on every page, with the same order of items.

Responsive behaviour

BreakpointShowsHeight
Desktop (1280px and up)Logo · five menus · Login | Request Demo · menu button80px
Tablet (768–1279px)Logo · Login | Request Demo · menu button86px
Mobile (767px and below)Logo · menu button72px

Items hidden at smaller sizes move into the menu panel, so nothing is lost. The panel opens below the bar and lists every menu item, then Login and Request Demo (proposed).

Light and dark theme

In Figma the header component has its theme mode set to dark. In code, put data-theme="dark" on the <header>. Its tokens then resolve to dark values even when the page is light.

Each header variant also sets the breakpoint and typography modes for its size. The Mobile variant doesn't set typography yet. That's harmless today, because it has no text, but it should be set (see Figma audit).

Microcopy and limits

  • Menu labels: 1–3 words, 20 characters max, title case as in Figma ("Tekion AI Agents").
  • Header CTA: 2–3 words, 16 characters max ("Request Demo").

Developer implementation

<header class="wds-header" data-theme="dark">
  <div class="wds-header__bar">
    <a class="wds-header__logo" href="/"><img src="/assets/logos/tekion-logo.svg" alt="Tekion home"></a>
    <nav class="wds-header__nav" aria-label="Main">
      <ul>
        <li class="wds-header__item">
          <button class="wds-navlink" aria-expanded="false" aria-controls="dd-products" data-wds-toggle>Products …chevron…</button>
          <ul class="wds-header__dropdown" id="dd-products" hidden>…</ul>
        </li>
        <li class="wds-header__item"><a class="wds-navlink" href="/testimonials">Testimonials</a></li>
      </ul>
    </nav>
    <div class="wds-header__actions">
      <a class="wds-navlink wds-header__login" href="/login">Login</a>
      <span class="wds-header__divider" aria-hidden="true"></span>
      <a class="wds-navlink wds-header__demo" href="/demo">Request Demo</a>
      <button class="wds-btn wds-btn--icon-m" aria-expanded="false" aria-controls="menu-panel"
              aria-label="Open menu" data-label-open="Close menu" data-label-closed="Open menu" data-wds-toggle>…menu…</button>
    </div>
  </div>
  <nav class="wds-header__panel" id="menu-panel" aria-label="Menu" hidden>…</nav>
</header>

js/wds.js handles data-wds-toggle: it opens one menu at a time, closes on Escape (returning focus to the trigger) and closes on an outside click.

Accessibility

  • Use <header> and <nav aria-label="Main"> landmarks, and add a "Skip to content" link before the header (WCAG 2.4.1).
  • Menu triggers are buttons with aria-expanded. Plain links stay links.
  • The menu button's accessible name changes between "Open menu" and "Close menu".
  • Logo alt text is "Tekion home" because it's a link to the home page.
  • The divider between Login and Request Demo is decorative: aria-hidden="true".

Needed from Design

  • Open states for the five menus (dropdown or mega menu).
  • The menu panel for tablet and mobile.
  • Behaviour on scroll: sticky, hide on scroll down, or static.
  • Hover and focus states for menu items.

Acceptance checklist

  • The header is dark in both page themes.
  • Desktop, tablet and mobile show the items in the table above.
  • Every menu and the menu panel open and close with mouse, touch and keyboard, and Escape closes them.
  • Skip link and landmarks are present.
