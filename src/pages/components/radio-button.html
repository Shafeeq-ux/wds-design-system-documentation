Overview

Radio buttons let people choose exactly one option from a short list, with every option visible. Once one is chosen, people can change it but can't clear the group.

Variants and states

Proposed states mirror the checkbox: Default, Focus, Checked, Disabled and Checked-disabled.

Anatomy

PartProposed spec
Circle20px, full radius · checkbox border and background tokens
Dot8px, checkbox-icon-checked, centred
Gap and label12px · Body 4 Regular, aligned to the first line

Design guidance

Do

  • Use radios for 2–6 mutually exclusive options.
  • Order options logically (smallest to largest, or most common first).
  • Preselect an option only when it's a safe default.

Don't

  • Use a single radio button. Use a checkbox.
  • Use radios for more than about 6 options. Use a dropdown.

Responsive behaviour and theme

Same as Checkbox: fixed size, stacked options on mobile, and colours that invert in dark mode.

Developer implementation

  <label class="wds-radio"><input type="radio" name="rooftops" value="2-5"><span>2–5</span></label>
</fieldset>

Accessibility

  • Group radios in a fieldset with a legend, and give them the same name (WCAG 1.3.1).
  • Tab moves into the group; arrow keys move between options and select them (WCAG 2.1.1). Native radios do this for free.

Needed from Design

  • A radio component set with the five states, in light and dark.
  • Confirmation of the dot size and whether radios should use their own tokens.

Acceptance checklist

  • Design has signed off the component in Figma.
  • Native radios, grouped in a fieldset with a legend.
  • Arrow-key navigation works.
