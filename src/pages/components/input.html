Overview

Inputs collect information in forms. WDS has five, all sharing the same surface, sizes and states:

InputFigma componentUse for
Text field[c]-input-textfieldShort free text, such as a name or company.
Email[c]-input-emailAn email address. Has a leading envelope icon.
Phone[c]-input-phoneA phone number, with the calling code shown separately.
Dropdown[c]-input-dropdownOne choice from a fixed list. Has a trailing chevron.
Textarea[c]-input-textareaLonger comments that may run over several lines.

Variants and states

Every input has five states: Default (placeholder), Filled, Focus (2px border), Error (red border and message) and Disabled. The fields in this preview are live: click into one to see the real focus state.

Radius mismatch. The Figma inputs measure 8px, but the border-radius/input token is 9999 (a pill). The CSS uses the measured 8px. Design should update the token or the components.

Design guidance

Do

  • Give every field a visible label above it.
  • Use the specific input for the data: Email for emails, Phone for numbers.
  • Write error messages that say how to fix the problem.
  • Mark required fields, or say which fields are optional, consistently across a form.

Don't

  • Use the placeholder as the label. It disappears when people type.
  • Use a dropdown for fewer than 4 options. Use radio buttons.
  • Show an error before someone has finished the field.

The Figma components have no label layer and put the field name in the placeholder ("First name"). The live examples add a label above, which the WCAG guidance in the Figma handbook also recommends.

Responsive behaviour

  • Inputs fill their container's width. Figma specimens are 280px wide.
  • In forms, put two fields side by side on desktop (for example first and last name) and stack them on mobile.
  • The 16px value size stops iOS from zooming in when a field gets focus. Don't make it smaller.

Light and dark theme

The input background is gray at 15% opacity (white in light, gray-900 in dark). That's designed for forms that sit on gradient or image sections: the field tints whatever is behind it. On a plain page it looks transparent.

Low-contrast border. input-border (gray-200) is 1.37:1 on white and 1.62:1 on the dark page. WCAG 1.4.11 needs 3:1 for the edge of a field. Use gray-400 in light and gray-500 in dark. See Known issues.

Microcopy and limits

  • Labels: 1–3 words, 25 characters max, Title Case as in Figma ("First Name", "Work Email"), no colon.
  • Placeholders: an example of the format ("name@company.com"), never instructions people need to remember.
  • Errors: one sentence, 60 characters max, that says what to do: "Enter an email address like name@company.com", not "Invalid input".
  • Dropdown options: 30 characters max each, in a logical or alphabetical order.

Developer implementation

<div class="wds-field">
  <label class="wds-field__label" for="email">Work email</label>
  <div class="wds-input">
    <svg aria-hidden="true">…mail…</svg>
    <input id="email" type="email" autocomplete="email"
           placeholder="name@company.com" aria-describedby="email-msg">
  </div>
  <p class="wds-field__msg" id="email-msg"></p>
</div>
NeedHow
ErrorSet aria-invalid="true" on the control and add is-error to the message. The surface turns red through :has().
DisabledAdd disabled to the control. The surface styles itself.
DropdownAdd .wds-input--select, use a native <select required> with a hidden empty first option, and put the chevron SVG after it.
PhonePut <span class="wds-input__prefix">+1</span> before type="tel". There's no country picker in Figma.
TextareaAdd .wds-input--textarea.

Use the is-focus, is-error and is-disabled classes only for static specimens. Real pages should rely on :focus-within, aria-invalid and disabled.

Tokens

Accessibility

  • Every input has a <label for>. Placeholders are not labels (WCAG 1.3.1, 3.3.2).
  • Connect messages with aria-describedby, and set aria-invalid on error (WCAG 3.3.1).
  • Use the right type and autocomplete so browsers and password managers can fill fields (WCAG 1.3.5).
  • Errors use colour and text, never colour alone (WCAG 1.4.1).
  • The focus state is a 2px border, which is visible against the page in both themes (WCAG 2.4.7).

Acceptance checklist

  • Each field has a visible label and the right type and autocomplete.
  • All five states match Figma in light and dark.
  • Error messages are linked with aria-describedby and say how to fix the problem.
  • The message space is reserved, so errors don't shift the layout.
  • The value text is 16px on mobile.
