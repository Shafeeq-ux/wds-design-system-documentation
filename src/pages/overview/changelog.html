3.0.1 · 17 October 2026

  • Token map on every section page and on Button, Input, Checkbox, Header and Banner (Radio button has no Figma component yet): the Figma render with every layer's colour, type, spacing and border variables, their CSS names and values per breakpoint and theme, padding and gap overlays, CSS for each layer, and untokenised values flagged as issues.
  • Icons: every utility icon and all 65 feature icons (light versions, exported from Figma) can be downloaded as SVG files or copied as SVG code. The feature icons replace the Icon Library image.
  • About: a Team section. Site audit: Design confirmed /faq and /trust-portal/privacy as WDS 2.0.
  • Figma to Webflow: a new page explaining how designs are converted into Webflow with the Figma to Webflow plugin, and the three variable collections (breakpoint, typography, theme) every section applies.
  • Variable modes section added to every section page, with a Figma audit of all 174 section, header and banner variants.

Open issues found

  • Hero default: the gap between each stat value and its label is a hardcoded 8px.
  • Card grid 4-column: the gaps inside cards (64, 37 and 80px) aren't tokenised, and the card copy has no single text style.
  • Button: the tertiary icon circle has a hardcoded 6px padding.
  • Feature platform architecture: the 16px card and icon-row gaps, the 6px icon-circle padding and the 32px Mobile container padding aren't tokenised.
  • Accordion right-image: the list gaps (4 to 48px) and the 80px image gap aren't tokenised, and the decorative gradients aren't bound to variables.
  • Carousel AI video: the container's 60px padding and 80px gap, the image-group gaps and the control pills' fills, strokes, padding and radii aren't tokenised, and the control label has no text style.
  • Tabbed UI: the tab bar and tab buttons (padding, radii, strokes, gradient) aren't tokenised, the tab labels have no text style, and Mobile has a hardcoded 70px column gap.
  • Comparison: the cards' 48px padding (24px on Mobile) and 16px gap aren't tokenised.
  • Video AI single and Pop-up video carousel: the video player controls use hardcoded fills, radii and padding with an unbound gradient, and "Video duration" has no text style.
  • Pop-up video carousel: the card padding, the row and column gaps and the 61px bottom padding aren't tokenised.
  • Bento five-image: the card padding (40px Desktop, 32px Tablet and Mobile) and 40px gap aren't tokenised, and the card copy has no single text style.
  • Testimonial default: most card padding and gaps (2 to 120px) are hardcoded, and the card overlays' gradients aren't bound to variables.
  • Stats platform: the gap between stats (140px Desktop, 24px Tablet and Mobile) and each stat's 24px top padding and 8px inner gap are hardcoded.
  • FAQ: the question-list gaps (4 to 49px) aren't tokenised.
  • Footer: most gaps aren't tokenised, including the navigation lists (8 to 32px), the social icons (16 to 48px) and a 616px spacer gap on Desktop.
  • Legal detail: the background and table cells use a hardcoded #ffffff fill, and the table and list padding and gaps aren't tokenised.
  • Form content: the form card's #000000 fill, #5671ad stroke, padding and gap, the input padding and the #b2dafa decorative ellipses aren't tokenised, one text layer has no text style, and the icon tiles' radii and gradients aren't tokenised.
  • Header: the 269px container gap and the navigation items' padding and gaps aren't tokenised, and the Mobile variant sets no typography mode.
  • Banner: the 12px gap, 6px icon padding and the vertical padding aren't tokenised, and the image banner artwork's gradients aren't bound to variables.
  • Inputs (all five): the field's 12px and 16px padding, the 8px icon gap and the 4px error-message gap aren't tokenised.
  • Accordion left-image: Desktop and Tablet variants don't set breakpoint or typography modes.
  • Legal implementation terms: the Tablet variant uses the desktop typography mode.
  • Legal disclaimer: the Desktop variant sets no modes.

3.0.0 · 17 October 2026

First release of the WDS 3.0 documentation site.

Documentation

  • Overview, Developer resources and Page templates: purpose, accessibility standard, contribution, governance and versioning; getting started, tokens, theming, responsive and browser support; four page templates.
  • Content guidelines: voice and tone, headings, CTA labels, character limits with a calculator, alt text, accessibility copy, localisation, and SEO and metadata.
  • Section layouts: 16 sections, 55 variants rendered from Figma, character limits for 90 content slots, and live examples for Hero, Card grid, Feature, Stats, FAQ and Footer.
  • Components: Button, Input, Checkbox, Radio button (proposed), Header and Banner, with live examples.
  • Foundations: colour with contrast checks, typography, type in use, spacing, grid and breakpoints, borders and radii, gradients, elevation, motion, logos and icons.
  • Site: tokens generated from Figma, light/dark/system theme, viewport previews, search, and a link checker.

Open issues found during documentation

  • Primary button colour tokens don't match the image fill the component uses, and are white on white in dark mode.
  • Input radius token (9999) doesn't match the 8px components.
  • Input and checkbox borders, teal text and light-mode error text are below WCAG contrast minimums.
  • No Radio button component, focus states, elevation or motion tokens in Figma.
  • Header menus and the mobile menu panel aren't designed.
  • CTA wording and heading case are inconsistent in a few places.
