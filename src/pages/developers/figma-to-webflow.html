Overview

tekion.com is built in Webflow. WDS 3.0 pages are designed in Figma and converted into Webflow pages with the Figma to Webflow plugin. Because the plugin carries the Figma variables across, the same tokens drive the design in Figma and the live page in Webflow.

1FigmaSections built from WDS components, with every value bound to a variable
→
2Figma to Webflow pluginConverts the frames and variables into Webflow elements, classes and variable collections
→
3WebflowPages assembled from the converted sections and published to tekion.com

This documentation site isn't part of that pipeline. It documents the system, and its CSS (tokens.css, wds.css) is a reference build of the same Figma variables, so the live examples behave like the Webflow pages.

Three variable collections on every section

Every section component applies three Figma variable collections. Together they give a section its responsive spacing, responsive typography and light or dark theme, in Figma and again in Webflow.

CollectionModesControlsFoundation page
breakpointdesktop · tablet · mobileSection padding, gaps, container and text widths, card column widthsGrid & breakpoints
typographydesktop · tablet · mobileFont size, line height and letter spacing of all 27 text stylesTypography
themelight · darkBackgrounds, text, icons, borders, status and component colours, gradient stopsColour

How a section sets its modes

Each section is a component set with a Desktop, Tablet and Mobile variant. In the Figma Appearance panel, each variant sets one mode per collection:

  • breakpoint and typography always match the variant's size.
  • theme is the same on all three variants, and is the section's default (shown on each section page). Switching it to dark recolours the whole section without touching its layers.
  • Children inherit the section's modes. Don't set modes on layers inside a section unless a part must stay fixed, such as the image banner card that stays light.

Example: [section]-hero-default-wds-3.0 sets breakpoint = desktop, theme = light and typography = desktop on its 1920 × 1569 desktop variant.

Workflow

  1. Design in Figma with WDS components. Bind every colour, spacing, width, radius and text property to a variable or text style. A hard-coded value won't respond to modes.
  2. Set the three modes on each Desktop, Tablet and Mobile variant, as above.
  3. Check the variants by switching the theme mode to dark and back, and by comparing the three variants against the breakpoint tokens.
  4. Run the Figma to Webflow plugin on the page or section to convert it. The variable collections and their modes come across with it.
  5. Check in Webflow that the section uses the same three collections and modes, then preview it at each Webflow breakpoint and in both themes.
  6. Publish, then check the live page against the section's documentation page and character limits.

Before running the plugin

  • Every variant sets breakpoint, typography and theme, with breakpoint and typography matching the variant.
  • No detached instances, and no colours, sizes or spacing typed in by hand.
  • Text uses WDS text styles, not local overrides.
  • Images are exported at 2× and have alt text ready.
  • Copy fits the section's character limits at mobile width.

Known limitations

To confirm with the Webflow team. These depend on the Webflow project's setup, not on Figma.

  • Breakpoint mapping. Figma designs at 1920, 768 and 390px. Confirm which Webflow breakpoints use the desktop, tablet and mobile modes. This documentation site's reference CSS switches at 1279px and 767px.
  • Image fills. The primary button's background is an image fill in Figma. Confirm the plugin carries it as an image, not a flat colour.
  • Gradients. Gradient styles use theme variables for their stops. Confirm they switch with the theme in Webflow.
  • Fonts. Webflow needs the Tekion Sans variable font uploaded so the 105%, 110% and 125% width settings render (see Type in use).
